# Tests

## Read before editing

- `docs/contributing/ci-test-pools.md`: how the e2e suites are split into CI pools.

## Unit tests

- Use **Ginkgo/Gomega**, not stdlib `t.Run`, and match the file you are adding to. `suite_test.go` in each package sets up envtest. Put new specs under an existing `Describe` where possible. Table-driven tests are fine and common: `DescribeTable` / `Entry`, or a slice of cases inside an `It`.
- **Exception: `tools/` uses stdlib `testing`**, not Ginkgo (see `.claude/rules/tools.md`).
- Run one spec from `operator/` with `./bin/ginkgo run --focus "describe text" ./internal/controller/...`, or `go test -mod=vendor -run TestName ./internal/graph/...` for packages with stdlib tests.
- `make watch-tests` (in `operator/`) runs Ginkgo in watch mode.
- Mocks are generated by mockery. After editing a mocked interface, run `make generate-mocks` in that module; hand-edited mocks drift.

## Unit vs. e2e

Unit tests use **envtest** (a fake apiserver). E2e tests use **chainsaw** against a real kind cluster, under `k8s-tests/chainsaw/{nodewright,cli,helm,deployment-policy}`. Don't mix them: a test that needs real pods running belongs in `k8s-tests/chainsaw/`, not `operator/internal/controller/`.

## Running e2e

- The e2e suites need a working `kind` (version pinned in `operator/versions.yaml`) and a running container runtime; the Makefile installs neither. ctlptl and chainsaw are downloaded for you.
- `make create-kind-cluster` builds a fresh cluster with registry credentials wired up; `make create-deployment-policy-cluster` builds the 15-node cluster the deployment-policy suite needs.
- `make e2e-tests` runs chainsaw against the current cluster; set `POOL=<name>` to run one pool.
- `DOCKER_CMD` defaults to `docker`; pass `DOCKER_CMD=podman` to use podman.
- `make test` in `operator/` is heavy: it runs unit tests plus four e2e suites and expects a running cluster. It also needs `AGENT_IMAGE` set to the chart's pin, which has no default: `AGENT_IMAGE="$(make -s print-chart-agent-image)" make test`. For quick iteration use `make unit-tests` or `make watch-tests`.
- `make operator-agent-tests` needs the same `AGENT_IMAGE`; without it the target stops at its guard.
